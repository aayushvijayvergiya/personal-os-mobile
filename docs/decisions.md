# Implementation decisions log

Record here any choice the implementer had to make that `docs/plan.md` did not cover. One entry per decision: date, phase, what was chosen, why, and which plan section it relates to.

| Date | Phase | Decision | Why | Plan ref |
|---|---|---|---|---|
| 2026-09-06 | 0 | Auth gating uses Expo Router's `Stack.Protected` guards in `app/_layout.tsx` instead of redirect effects. | Declarative, no flash of the wrong screen, documented for SDK 53+. | §5.2 |
| 2026-09-06 | 0 | `react-dom` is pinned as a dev dependency at the same version as `react`. | A transitive dep resolved `react-dom@19.2.8`, which peer-requires a newer `react` than Expo SDK 57 pins; pinning resolves the npm ERESOLVE. | §4 |
| 2026-09-06 | 1 | Retro font is **Pixelify Sans**, not Silkscreen / VT323 / Press Start 2P. | Owner chose a retro font over the system font. Of the OFL pixel faces on Google Fonts, only Pixelify Sans and Silkscreen ship a true bold (the theme needs one), and Pixelify Sans is proportional with a normal x-height, so journal paragraphs stay readable where Silkscreen's bitmap face would not. | §3 |
| 2026-09-06 | 1 | Bold text swaps to the 700 font file instead of setting `fontWeight: "bold"`. | With a bundled pixel face, `fontWeight` produces faux-bold smearing on Android. `Txt` drops `fontWeight` whenever `theme.font.bold` is set. | §5.6 |
| 2026-09-06 | 1 | `Progress` renders ~20 discrete segments rather than a striped continuous fill. | React Native has no `repeating-linear-gradient`; the segmented bar is both simpler and closer to the real Win95 progress control. | §5.6 |
| 2026-09-06 | 1 | `DateField` uses the imperative `DateTimePickerAndroid.open()` on Android and an inline picker inside a `Dialog` on iOS. | The community picker's documented per-platform usage; rendering the component on Android is discouraged. | §5.6 |
| 2026-09-06 | 3 | Dialogs (`TaskPropertiesDialog`, `GoalDialog`, `ProjectDialog`) are fully controlled: the parent owns the draft row. | The alternative, syncing an internal `useState` from props in an effect, is the `react-hooks/set-state-in-effect` anti-pattern and fails lint. | §7.3 |
| 2026-09-06 | 3 | Screens scroll as a whole page rather than nesting a scrolling list inside a fixed panel. | Matches the web app, avoids nested-scroll conflicts, and keeps pull-to-refresh working on every module. | §5.4 |
| 2026-09-06 | 4 | `JournalBody` is mounted with a `key` of `type:date` so switching day resets the draft. | Same reason as the controlled dialogs: it resets state without a syncing effect. | §7.4 |
| 2026-09-06 | 5 | `calendarItems()` takes a palette argument instead of importing theme colours. | Keeps the function pure and unit-testable while still letting task colours follow the active theme; only the goal teal and article purple are fixed. | §7.9 |
| 2026-09-06 | 7 | The Notes search box sits in the window body, not the title bar. | A phone title bar has no room for a text field beside the title. | §7.10 |

| 2026-09-06 | post-QA | Typeface changed from Pixelify Sans to **IBM Plex Sans**, and a typeface picker (IBM Plex Sans / System) was added to Settings → Display. | Owner reported the pixel face was not legible on device.
